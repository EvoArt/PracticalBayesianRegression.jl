Fitting

PracticalBayesianRegression.PracticalBayesianRegression — Module
PracticalBayesianRegression

Bayesian regression models in the style of R's brms: brms formula syntax, families and default priors, and brms parameter names. Each model's log density and its gradient are built directly from the formula and sampled with the package's own NUTS. Start with brm and @bf.

Fitting a model

PracticalBayesianRegression.brm — Function
brm(formula, data; family = gaussian(), prior = PriorSpec[], kwargs...) -> BrmsFit

Fit a Bayesian regression model, as brms's brm. By default the posterior is sampled with NUTS: 4 chains of 2000 iterations, the first half warm-up.

Arguments

  • formula: a formula from @bf or bf, or a formula string. Adding formulas (@bf(y1 ~ x) + @bf(y2 ~ x)) gives a multivariate model, whose result is a BrmsMVFit.
  • data: any Tables.jl table, such as a DataFrame or a NamedTuple of vectors. Rows with missing values in the variables the model uses are dropped, with a warning, unless the model imputes them (mi()).

Keywords

  • family: the response distribution, e.g. poisson() or bernoulli(link = :probit), or a brms family name ("poisson"); see brmsfamily. A vector gives one family per response of a multivariate model.
  • prior: a vector of prior rows. Parameters without one get brms's default prior (see get_prior).
  • data2: a NamedTuple of extra data that is not one row per observation, such as the matrices of car(W) or gr(g, cov = A).
  • chains = 4, iter = 2000, warmup = iter ÷ 2, thin = 1: the number of chains, iterations per chain (warm-up included), warm-up iterations and the thinning interval.
  • seed: an integer for reproducible results.
  • delta = 0.8: the target acceptance rate (brms's adapt_delta). Raise it (to 0.95, say) when the fit reports divergent transitions.
  • max_depth = 10: the maximum tree depth (brms's max_treedepth).
  • metric = :diag: the mass matrix adapted during warm-up, :diag or :dense (see the sampler guide).
  • init = 2.0: initial values are drawn uniformly from (-init, init) on the unconstrained scale.
  • threads = true: run the chains in parallel when Julia has more than one thread (start Julia with -t 4).
  • sampler = :nuts: the package's NUTS; :advancedhmc or an AdvancedHMC.AbstractHMCSampler uses AdvancedHMC.jl instead.
  • algorithm = :sampling: or :laplace, :meanfield, :fullrank, :pathfinder for an approximate posterior of ndraws = 1000 draws.
  • sample_prior = :no: :yes also draws from the priors (for hypothesis); :only samples the prior alone, which needs a proper prior on every parameter.
  • mi = :auto: how missing values modelled with mi() are handled. :auto integrates them out where that is exact or accurate by quadrature and samples the rest; :sample samples every missing value, as brms does.
  • T = Float64: the floating-point type of the sampler (Float32 for single precision).

Examples

fit = brm(@bf(y ~ x + (1 | g)), df; family = poisson(), seed = 1)
fit = brm("y ~ x", df; prior = [prior("normal(0, 1)"; class = :b)])
fit = brm(@bf(y ~ x), df; chains = 4, iter = 4000, delta = 0.95)

PracticalBayesianRegression.BrmsFit — Type
BrmsFit

A fitted model, returned by brm. Displaying it prints brms's summary table. Get the parameter names with variables and their draws with draws; fit.chain holds the draws as a FlexiChains.FlexiChain keyed by the same names.

source
PracticalBayesianRegression.BrmsMVFit — Type
BrmsMVFit

A fitted multivariate model. fit["y"] is response y's own BrmsFit (sharing the joint draws), so every univariate tool — summaries, predictions, LOO, plots — works per response. The joint chain uses brms's multivariate names (b_y_x, sigma_y, rescor__y__y2).

PracticalBayesianRegression.update — Function
update(fit; newdata=nothing, formula=nothing, kwargs...)

Refit with some arguments changed, as brms's update (any brm keyword: family, prior, chains, iter, seed, ...). Only fits made by brm remember their arguments.

PracticalBayesianRegression.brm_multiple — Function
brm_multiple(formula, datasets; seed = nothing, kwargs...) -> BrmsFit

Fit the same model to each data set (for example, multiple imputations) and pool the chains, as brms's brm_multiple. Other keywords go to brm. Because the data sets differ, R-hat of the pooled chains is not a convergence check; check the fits one by one.

source
PracticalBayesianRegression.combine_fits — Function
combine_fits(fits) -> BrmsFit

Pool the chains of several fits of the same model, as brms's combine_models: for example, fits to multiply imputed data sets. Every fit must have the same parameters and number of draws per chain.

Building and sampling in two steps

PracticalBayesianRegression.build_model — Function
build_model(formula, data; family=gaussian(), prior=PriorSpec[], T=Float64)
    -> (GLMDensity, ModelInfo)

Construct the log density of a brms-style model without sampling it. data is any Tables.jl table (a DataFrame, a NamedTuple of vectors, ...). T is the element type of the parameter vector and of the stored design matrices (use Float32 for a single-precision sampling path). sample_prior=:only drops the likelihood (brms's sample_prior = "only"): the fit is then a draw from the prior, and its posterior_predict is the prior predictive.

source

build_mv_model(formula, data; family=gaussian(), prior=PriorSpec[], T=Float64)
    -> (MVDensity, Vector{ModelInfo})

The multivariate counterpart of build_model. family is one family for every response or a vector with one per response; priors apply to every response unless given resp = "name".
