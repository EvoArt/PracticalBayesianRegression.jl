Model binaries

See Build a model binary.

PracticalBayesianRegression.build_binary — Function
build_binary(formula, data; family=gaussian(), prior=PriorSpec[], output="model",
             name="model", juliac=nothing, cc=nothing, verbose=true) -> executable path

Compile a model into a standalone executable that refits it to any CSV file with the same columns, much as a CmdStan executable refits its model to new data:

$ model/bin/model --data new.csv --output draws.csv --chains 4 --seed 1

data is example data: it fixes which columns are numeric and which are factors, and the build checks the compiled model against brm on it. The executable writes the draws as CSV with brms parameter names and prints a summary table; --help lists its options. It needs no Julia installation: distribute the whole output directory.

Building needs Julia 1.12 or later, a C compiler and JuliaC: by default the juliac app on the PATH (pkg> app add JuliaC); otherwise pass juliac as a Cmd, e.g. $`julia --project=/path/to/env -e "using JuliaC; JuliaC.main(ARGS)" --`$. cc sets the C compiler command. A run with --seed s gives the same draws as brm(formula, data; family, prior, seed = s).

Not every model can be compiled yet; an unsupported feature raises an ArgumentError that names it (see model_recipe).

PracticalBayesianRegression.model_recipe — Function
model_recipe(formula, data; family=gaussian(), prior=PriorSpec[]) -> (recipe, atoms)

Build the model once with the front end and extract its ModelRecipe. Throws an ArgumentError naming every feature a recipe does not support yet, and verifies that re-assembling data from the recipe reproduces build_model exactly. atoms (the front end's atoms, in recipe order) is what code generation for a model binary needs.

Model store

PracticalBayesianRegression.compile_model — Function
compile_model(formula, data; family = gaussian(), prior = PriorSpec[], name = nothing,
              store = model_store(), force = false, juliac = nothing, cc = nothing,
              keys = String[], verbose = true) -> CompiledModel

Compile a model into a standalone executable (see build_binary) and keep it in the model store, or return the stored one if this formula, family, priors and column types were compiled before (force = true rebuilds). Fit it to any data with the right columns with brm(model, data); find it again in a later session with compiled_model or compiled_models, or by calling compile_model with the same arguments.

name defaults to <response>_<family>_<hash>. juliac defaults to the environment variable PBR_JULIAC (a command line, e.g. julia --project=/path/env -e "using JuliaC; JuliaC.main(ARGS)" --), else the juliac app on the PATH. keys are extra lookup keys to register (the R package passes its own).

PracticalBayesianRegression.compiled_models — Function
compiled_models(; store = model_store()) -> ModelStore

Every compiled model in the store that runs on this machine (models built on another operating system are skipped), newest first. Index the result by name: compiled_models()["mymodel"].

source
PracticalBayesianRegression.compiled_model — Function
compiled_model(name; store = model_store()) -> CompiledModel

A compiled model, by its name in the store, the path of its directory, or the path of its executable (.../mymod/bin/mymod). The model is callable: m = compiled_model("mymod"); fit = m(data; chains = 4) is brm(m, data; chains = 4).

PracticalBayesianRegression.model_store — Function
model_store() -> String

The directory compiled models are kept in: the environment variable PBR_MODEL_STORE if set, else ~/.pbr/models. The R package uses the same default, so models compiled from either language are found by both.
