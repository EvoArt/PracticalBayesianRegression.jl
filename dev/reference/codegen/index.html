Code generation

See Generate Turing or PracticalBayes code.

PracticalBayesianRegression.turing_code — Function
turing_code(formula, data; family, prior, ...) -> ModelCode
turing_code(fit::BrmsFit)
turing_code(ld::GLMDensity, info::ModelInfo)

Turing.jl @model source code for the model that brm fits, to read, edit or extend by hand; the counterpart of brms's stancode. The arguments are those of brm, or a fit. The model takes the data from model_data as positional arguments:

code = turing_code(@bf(y ~ x + (1 | g)), d; family = poisson())
write("model.jl", code)                  # edit it, then include("model.jl")
m = regression_model(model_data(@bf(y ~ x + (1 | g)), d; family = poisson())...)

turing_model does the evaluation step for you. The keyword name (default :regression_model) names the generated function.

Every model that brm fits gets code. Where the generator can write a model's features out, the code is explicit: named parameters, Distributions.jl priors, the linear predictors and the likelihood. For other models it samples the unconstrained parameter vector θ and adds the package's own log density (model_logdensity); code.fallback then names the feature responsible, and fallback = false raises an error instead.

The generated model is sampled with Turing's samplers and automatic differentiation, so it is not guaranteed to be as fast as brm.

PracticalBayesianRegression.pb_code — Function
pb_code(formula, data; family, prior, ...) -> ModelCode
pb_code(fit::BrmsFit)
pb_code(ld::GLMDensity, info::ModelInfo)

PracticalBayes.jl @model source code for the model that brm fits. It works as turing_code does; only the package the code loads differs. To run it, install PracticalBayes.jl, include the code and call the model function with the arguments from model_data.

PracticalBayesianRegression.turing_model — Function
turing_model(formula, data; family, prior, ...) -> DynamicPPL.Model
turing_model(fit::BrmsFit)

The generated Turing model (turing_code), evaluated and applied to its data, ready for sample(m, NUTS(), MCMCThreads(), 1000, 4), maximum_a_posteriori(m) and so on. Needs using Turing.

The model function is defined when this is called. Inside a function or loop that calls turing_model and then samples, call Base.invokelatest(sample, m, ...); at the REPL or the top level of a script no extra step is needed.

PracticalBayesianRegression.model_logdensity — Function
model_logdensity(density, θ) -> Real

The log density that brm samples (constants dropped, Jacobians included) of a built model at the unconstrained point θ, written in generic Julia code that any automatic differentiation backend can differentiate. Generated model code calls it for models it cannot write out explicitly (see turing_code).

Helpers used by generated code

PracticalBayesianRegression.FamilyDist — Type
FamilyDist(family, x, trials, eta...)

The distribution of one observation under a package family, given its distributional parameters on the LINK scale (eta, in the family's dpar order: mu, sigma, ... as log(sigma), ...) and the family's per-observation data x (e.g. log(y), censoring codes, truncation bounds) and trials. logpdf is the package's own (normalised) log-likelihood and rand its posterior-predictive draw, so it is exact for every family brm fits.

Generated model code (turing_code) uses it for families with no Distributions.jl equivalent, the way brms's Stan code defines such families in its functions block.
