Generate Turing or PracticalBayes code

turing_code writes the model that brm fits as a Turing.jl @model, the way brms's stancode writes Stan code. Use it to see exactly what a formula means, or as a starting point for a model that brms syntax cannot express. pb_code does the same for PracticalBayes.jl.

using PracticalBayesianRegression

f = @bf(y ~ x + (1 | g))
code = turing_code(f, df; family = poisson())
using Turing, LinearAlgebra
# Generated by PracticalBayesianRegression.turing_code.
# formula: y~x+(1|g)
# family:  poisson (log link)
# Data: `model_data(...)` returns the arguments in order.
@model function regression_model(y, X, means_X, J_g, N_g)
    # population-level effects (X is centred; Intercept is the centred intercept, as in brms)
    Intercept ~ 2.5 * TDist(3)
    b ~ filldist(Flat(), 1)
    b_Intercept := Intercept - dot(means_X, b)
    # group-level effects (Intercept | g), non-centred as in brms
    sd_g ~ truncated(2.5 * TDist(3); lower=0)
    z_g ~ filldist(Normal(), N_g)
    r_g = sd_g .* z_g
    eta = Intercept .+ X * b .+ r_g[J_g]
    # likelihood
    y ~ arraydist(LogPoisson.(eta))
end

The code uses the same design matrices, centring, parameterisation and default priors as brm. model_data returns the arguments it takes. turing_code(fit) writes the code for a fitted model.

Edit and run it

Save the code, change it, and run it with Turing:

write("model.jl", code)
# ... edit model.jl ...
using Turing
include("model.jl")
m = regression_model(model_data(f, df; family = poisson())...)
chain = sample(m, NUTS(), MCMCThreads(), 1000, 4)

To run the generated model unchanged, turing_model evaluates the code and applies it to the data in one step:

using Turing
m = turing_model(f, df; family = poisson())
chain = sample(m, NUTS(), MCMCThreads(), 1000, 4)

turing_model defines the model function when it is called. Inside a function, sample through Base.invokelatest(sample, m, NUTS(), 1000).

Speed

The generated model is evaluated by Turing (or PracticalBayes) with automatic differentiation, not by this package's closed-form gradient, so it is not guaranteed to be as fast as brm, and is usually slower.

Models the generator cannot write out

Every model gets code, but not every feature can be written out explicitly yet. For those models the code samples the unconstrained parameter vector and adds the package's own log density with model_logdensity. The posterior is the same; the code is just less readable. code.fallback names the feature responsible:

code = turing_code(fit)
code.fallback          # "" when the code is explicit
turing_code(fit; fallback = false)   # raise an error instead

Families without a Distributions.jl equivalent appear as FamilyDist, the package's own distribution type for them.
