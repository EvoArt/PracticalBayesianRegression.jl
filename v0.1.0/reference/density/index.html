Log density interface

build_model returns a model's posterior log density as a GLMDensity, without sampling it. It implements the LogDensityProblems.jl interface, so any sampler or optimiser that accepts that interface can use it, and it has a closed-form gradient.

using PracticalBayesianRegression
import LogDensityProblems

ld, info = build_model(@bf(y ~ x + (1 | g)), df; family = poisson())
θ = zeros(LogDensityProblems.dimension(ld))
g = similar(θ)
lp = logdensity_and_gradient!(g, ld, θ)     # value, gradient written into g
names = variables(ld)
values = constrain(ld, θ)                   # natural-scale values of `names`

θ is on the unconstrained scale: standard deviations enter as their logs, correlation matrices through Stan's transforms, and so on. The density drops constant terms and includes the Jacobians of these transforms, as Stan's does. A GLMDensity holds scratch memory; give each thread its own copy with fresh_workspace.

PracticalBayesianRegression.GLMDensity — Type
GLMDensity

The posterior log density of a model (up to a constant), on the unconstrained scale, implementing the LogDensityProblems interface with a closed-form gradient.

Holds a scratch workspace, so one GLMDensity must not be shared between threads: fresh_workspace gives an independent copy per chain.

PracticalBayesianRegression.logdensity_and_gradient! — Function
logdensity_and_gradient!(g, ld, θ) -> logdensity

Closed-form log density (up to a constant) and gradient (written into g). θ must have the element type ld was built with.

PracticalBayesianRegression.fresh_workspace — Function
fresh_workspace(ld) -> GLMDensity

A copy of ld sharing all data but with its own scratch buffers, so chains on different threads never write to the same memory.

PracticalBayesianRegression.variables — Method
variables(ld) -> Vector{String}

Parameter names in brms's naming scheme (b_Intercept, b_x, sd_g__Intercept, cor_g__Intercept__x, sigma, Intercept, r_g[a,Intercept]), in the order constrain returns values.
